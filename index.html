      How to independently verify with F12 (Developer Tools)
      1. Open Developer Tools using F12 or Ctrl+Shift+I (Windows/Linux). On a Mac, press Command+Option+I or use the browser menu.
      2. Choose the Network tab, select All and enable Preserve log. The recording indicator should be active.
      3. Reload the page while the Network panel is open. Website assets such as the shared Mightora component scripts, styles, images and badge images may be requested.
      4. Choose a HAR file and run the analysis. Observe the Network panel. In particular, filter by Fetch/XHR to investigate any application requests and inspect their destinations.
      5. If you see unexpected requests, investigate the destination and payload before drawing conclusions. Disconnect from the internet and repeat with the offline edition when handling highly sensitive captures.

      Privacy tip: DevTools itself may display sensitive URLs or header data from other sites. Do not share an unreviewed network export.

      How to analyse a HAR file

      A HTTP Archive (HAR) captures browser network requests, timings, and responses. In Edge or Chrome, open Developer Tools → Network, reproduce the issue, and export the network log as HAR. Treat that capture as confidential.

      What this analyser detects

      4xx and 5xx errors, requests taking more than three seconds, responses larger than one megabyte, server wait time, DNS and connection delays, transfer totals, and latency percentiles.

      What we never do

      No HAR uploads, traffic replay, captured URL fetches, execution of response content, browser storage, account registration or application analytics. Content is handled locally by a Web Worker.

      Aggregate request durations are not page load duration, because network requests can occur concurrently. Timing estimates depend on the captured browser data.

      Frequently asked questions

      Will my HAR file be uploaded?

      No. The analyser reads the file in a local Web Worker. Shared brand components may still load from external CDNs, so consider running a vetted offline copy for particularly sensitive captures.

      Are my exports anonymous?

      Not necessarily. Reports remove cookies, authentication headers, bodies, URL query strings and many identifying path segments, but hostnames and other path information can remain. Review before sharing.

      Can I analyse a HAR file offline?

      Yes. Download the ZIP, extract har-analyser.html, and open it directly from your computer. This edition includes its own styles, JavaScript and logo; it does not fetch external libraries.

      What is a HAR file?

      A HTTP Archive (HAR) is a JSON-based record of a browser's network requests and timings, often exported from Developer Tools to investigate slow webpages or failing APIs.

      What causes slow requests in a HAR file?

      Likely causes include DNS lookup, connection setup, TLS negotiation, server processing and large transfers. Compare timing components to determine where to investigate further.

      How can I check which network requests this tool makes?

      Open the Network Transparency section for an on-screen summary. For an independent check, press F12 (or Command+Option+I on macOS), select the browser’s Network panel, enable Preserve log, reload the page and analyse a HAR. The online website may load styling, logos and badges; captured HAR data is not uploaded by the analyser.

      What does a slow server wait mean?

      A high wait value can indicate application processing, network latency or upstream work before the first byte. Correlate findings with server logs for a definitive diagnosis.
