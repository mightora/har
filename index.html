      How to analyse a HAR file

      A HTTP Archive (HAR) captures browser network requests, timings, and responses. In Edge or Chrome, open Developer Tools → Network, reproduce the issue, and export the network log as HAR. Treat that capture as confidential.

      What this analyser detects

      4xx and 5xx errors, requests taking more than three seconds, responses larger than one megabyte, server wait time, DNS and connection delays, transfer totals, and latency percentiles.

      What we never do

      No HAR uploads, traffic replay, captured URL fetches, execution of response content, browser storage, account registration or application analytics. Content is handled locally by a Web Worker.

      Aggregate request durations are not page load duration, because network requests can occur concurrently. Timing estimates depend on the captured browser data.

      Frequently asked questions

      Will my HAR file be uploaded?

      No. The analyser reads the file in a local Web Worker. Shared brand components may still load from external CDNs, so consider running a vetted offline copy for particularly sensitive captures.

      Are my exports anonymous?

      Not necessarily. Reports remove cookies, authentication headers, bodies, URL query strings and many identifying path segments, but hostnames and other path information can remain. Review before sharing.

      What does a slow server wait mean?

      A high wait value can indicate application processing, network latency or upstream work before the first byte. Correlate findings with server logs for a definitive diagnosis.

      Open-source quality and transparency

      Review the source code and its automated test and security-scanning workflows. Badges link to live workflow evidence and do not imply security certification.
